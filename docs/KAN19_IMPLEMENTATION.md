# KAN-19 interactive impact graph

Implemented with KAN-9 on `codex/kan9-impact-api` in draft PR #13, rebased onto
current main at `61e7283` (Drive refresh and extraction validation).

## Reviewer flow

The demo Reviews page loads the vendor-delay impact map. Reviewers can pan,
zoom, fit the graph, select a node, and inspect its ordered impact path. The map
distinguishes the evidence trigger, directly challenged launch decision, and
downstream integration and go-live decisions with labels and colors. Edges name
the direct challenge, `enables`, or `requires_review_of` relationship.

The detail panel shows decision ownership, rationale, and the description of each
relationship on the selected path. Multiple paths to a shared downstream decision
remain separately selectable. Selecting a path step opens that node's details.
The selected path's edges are highlighted.

The trigger and challenged decision show the original and updated evidence quotes,
typed values, and date delta. Downstream nodes show dependency rationale and an
explicit statement that they have no direct contradiction evidence. Their
“Inspect trigger evidence” button returns to the original finding. Synthetic demo
sources show quotes locally; live projections offer validated HTTP(S) source links.

Nodes support Tab focus and Enter/Space selection with announced selection status.
Zoom controls and the node list provide additional keyboard access. At narrow
widths, details move below the graph and path text wraps without horizontal overflow.
Relationships are read only: reviewers cannot drag nodes, reconnect edges, create
edges, or delete records through this graph.

## Data boundary

- Live graph: authenticated same-origin
  `GET /api/v1/projects/{projectId}/alerts/{alertId}/graph`.
- Demo graph: `GET /api/v1/projects/proj_demo_2026/fixture/alerts/alt_delivery_delayed/graph`.
  This route serves only the synthetic fixture, returns 404 for other IDs, and uses
  `private, no-store` plus an ETag.
- `fixtures/vendor-delay-impact.json` is generated by KAN-9's Python `ImpactService`
  from `fixtures/vendor-delay.json`. A regression check compares it with the live
  projection service so fixture changes cannot silently drift from API behavior.
- The browser validates projection scope, discriminated nodes, evidence fields,
  endpoint references, direct challenge, and complete ordered paths before rendering.
  It assigns presentation coordinates from supplied paths; it does not infer
  dependencies or calculate new impact paths.
- Pending requests are cancelled when the project or alert changes. Loading,
  missing graph, unauthorized project, stale review, and retry states are explicit.

A known live alert can be opened at
`/projects/{projectId}/reviews?alertId={alertId}`. The normal demo Reviews queue
opens its graph automatically. The live review-list endpoint is not available on
the current main; connecting that queue remains part of the review workflow work.

## Remaining integration

Jira links KAN-19 to KAN-9 and KAN-18 as blockers. KAN-18 supplies the complete
evidence viewer, including source type, locator, classification, confidence/coverage
states, and a fixture-controlled access-unavailable state that hides source metadata.
Its current MVP scope uses Firestore project roles and explicitly defers live
file-level ACL filtering and per-evidence Drive permission queries to KAN-11.
Those deferred permission checks are not a blocker for this PR. Native document
links could not be tested with synthetic URLs. Full KAN-3 → KAN-4 → KAN-16 → KAN-17
→ impact flow against root Doc, TXT, nested Doc, and saved Meet transcript sources
still needs testing after those prerequisites merge. The graph UI does not enable
review writes or revise decisions; those remain in the review workflow ticket.

The new graph packages have no advisories in the dependency audit. Nine high
findings remain in the pre-existing Firebase and lint dependency trees; this branch
does not change their locked versions.
